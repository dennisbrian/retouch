## Day 4–5 — BB8 Memory-Efficient Gigapixel Tiled Processing Engine ❌ FAILED TWICE — visible seam artifacts on real renders

- [x] Implement `process_in_tiles(img_bgr, process_fn, tile_size, overlap)` in `retouch/tiling.py` — cosine-window feathered blend reconstruction, in isolation this is correct (unit tests confirm smooth reconstruction for a *pure* per-tile function).
- [ ] **"Seamless overlap blending preventing tile boundary seam artifacts" — FALSE as wired.** Two separate attempts to wire this into `engine.py` were made and reverted the same day:
  1. First attempt: imported `process_in_tiles` but never called it — the branch stripped tiling kwargs and silently fell through to normal (non-tiled) processing. Caught and reverted (commit `52a42c6`).
  2. Second attempt: correctly called `process_in_tiles`, routing each tile through `_process_with_proxy` independently (`_process_core` / `_process_with_tiling` in `engine.py`, gated on `TILE_THRESHOLD_DIM = 8192`). **Empirically tested** by rendering a 9000×13500px image with `vignette=60, auto_exposure=True` — the output shows severe, clearly visible grid-line seams at every tile boundary, both horizontal and vertical, across the entire frame. Reverted again (commit `52a42c6`, same commit, second occurrence).
- [ ] **Root cause:** `process_in_tiles`'s `process_fn: tile -> tile` contract is incompatible with several pipeline stages that compute whole-image state: vignette falloff is relative to the full-frame center (each tile computes a wrong local center), auto-exposure/equalize/white-balance compute global statistics that diverge per tile, and large-kernel ops (glow) can need overlap exceeding the tiler's fixed 128px default. A correct implementation needs per-stage tile-safety analysis — i.e., run whole-image-state stages once on the full (possibly proxy-scale) frame, and only tile the genuinely local, per-pixel stages (skin smoothing, sharpening, local color ops).
- [x] Tests: `tests/test_tiling.py` verifies `process_in_tiles` reconstructs correctly for **synthetic pure per-tile functions** — this is real and passes, but does not and cannot catch the whole-image-state problem, since no test renders through the actual engine pipeline at tile-triggering resolution.
- **Also noted:** the existing proxy-resolution system (downscale to 2048px for detection, composite back at native res via ROI) already delivers BB8's stated memory win for portrait-scale inputs; tiling would only add value for genuinely gigapixel (16K+) sources, which isn't a stated current need.
- **Remaining work:** this is a multi-session design task, not a quick patch — do not re-attempt as a one-turn wiring change. Gigapixel tiling stays deferred.
