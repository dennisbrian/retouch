================================================================================
  THE PROBLEM & SOLUTION
================================================================================

PROBLEM:
  Cosplay characters often have intentional beauty marks (moles, marks) but 
  unwanted freckles. Current blemish removal treats all anomalies equally—
  it can't distinguish or preserve beauty marks.

SOLUTION:
  New FreckleRemover class adds classification layer:
  
  1. Detect all anomalies (same as blemish detection)
  2. Classify into: Freckle | Blemish | Beauty Mark | Noise
  3. Remove only freckles
  4. Preserve beauty marks
  5. Optional manual override via preserve_mask

EXAMPLE:
  Input:  Mitsuri face (Demon Slayer) with red freckles + strategic beauty mark
  → freckle_removal=75
  Output: Freckles removed, beauty mark preserved → Happy cosplayer

================================================================================
  FEATURE SCOPE (MVP)
================================================================================

USER CONTROLS:
  • freckle_removal: 0–100 slider
    - Default: 0 (off)
    - Higher = more aggressive freckle removal
  
  • freckle_preserve_mask: Advanced API
    - Base64-encoded PNG mask
    - User can manually protect regions if needed

WHAT GETS REMOVED:
  ✅ Freckles: small (4–20px²), red-tinted, clustered

WHAT GETS PRESERVED:
  ✅ Beauty Marks: large (15–60px²), dark, isolated
  ✅ Acne/Blemishes: handled separately (not this tool's job)
  ✅ User-specified regions: via preserve_mask override

PIPELINE POSITION:
  Image → Blemish Removal → Freckle Removal (NEW) → Under-eye Repair → ...

================================================================================
  RISK ASSESSMENT
================================================================================

Technical Risks (Mitigated):
  ✅ Heuristics generalize across skin tones
     → Use LAB color OFFSETS (relative to skin), not absolute thresholds
  ✅ Beauty marks aren't removed
     → Conservative size gates (≥15px²); preserve_mask fallback
  ✅ Performance OK
     → Single ConnectedComponents pass; ~1–2ms per face

UX Risks (Mitigated):
  ✅ User confusion (vs. blemish removal)
     → Separate parameters; clear labeling
  ✅ Can't preserve specific freckles
     → preserve_mask parameter for power users
  ✅ Makeup interactions
     → Tested with makeup scenarios; override available

Overall Risk: LOW (reuses proven architecture; clear requirements)
